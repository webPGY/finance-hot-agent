# Finance Hot Agent｜财经热点采集与排行平台

## 项目经历（简历版）

**项目描述：** 独立设计并实现财经热点采集与排行平台，面向 CNBC、Yahoo Finance 等公开 RSS 数据源，构建从数据采集、清洗去重、热度排序、每日摘要到 PostgreSQL 持久化和 Web 展示的自动化流程。提供首页榜单、历史归档、数据源切换、手动抓取及多时间点调度管理能力。

**项目业绩 / 工程成果：**

- 基于 LangGraph 将采集、去重、排名、摘要、持久化和空结果回退组织为可执行工作流；通过条件路由和 PostgreSQL Checkpointer 保存工作流状态。
- 统一财经新闻条目结构，按来源与规范化 URL 去重；按热度、发布时间及标题确定性排序，支持通过 `HOT_NEWS_COUNT` 配置榜单数量。
- 使用 PostgreSQL + Prisma 实现按日归档，采用 `(source, url, date)` 复合唯一约束，避免同一文章跨日抓取时覆盖历史记录；支持每日摘要与新闻数据持久化。
- 实现基于 `node-cron` 与数据库配置的多时间点任务，提供后台新增、启停、删除任务及手动触发抓取能力，默认配置早、中、晚三个任务时段。
- 实现热点首页与近 30 天历史查询页面；提供环境变量控制数据源与留存周期，支持过期热点和摘要清理。
- 建立 Node.js 原生测试覆盖去重、稳定排序、Top N 配置、日分区写入及数据源解析等核心逻辑；当前项目测试集包含 16 项用例。

**技术栈：** TypeScript、Next.js 15（App Router / Server Components / Route Handlers）、React 19、LangGraph、LangChain、PostgreSQL、Prisma、node-cron、Node.js 原生测试框架（`node:test`）。

## 项目介绍

Finance Hot Agent 是一个财经热点榜单应用。系统按配置周期或手动触发采集公开财经新闻，将不同来源的数据转成统一结构，执行噪声过滤、去重和排名，生成每日摘要后写入数据库，再由 Next.js 页面展示当前榜单和历史数据。后台支持数据源选择和抓取调度配置。

### 核心业务流程

```text
定时任务 / 手动触发
        ↓
公开 RSS 数据源采集
        ↓
统一字段与基础清洗
        ↓
按来源及 URL 去重
        ↓
按热度、发布时间排序并截取 Top N
        ↓
生成当日概览并写入 PostgreSQL
        ↓
首页 / 历史页查询展示
```

### 已实现功能

1. **数据采集与归一化**
   - CNBC 与 Yahoo Finance RSS 抓取器输出统一的来源、标题、URL、热度和发布时间字段。
   - 使用请求超时和 HTML 实体清理处理基础网络与文本问题。
   - 提供噪声过滤、重复标题合并，以及来源配置解析。

2. **LangGraph 工作流**
   - 由 scrape、dedup、rank、summarize、save 等节点组成 StateGraph。
   - 排名后根据结果是否为空进行条件路由；无有效条目时进入 fallback 分支。
   - 通过 PostgreSQL Checkpointer 接入 LangGraph 状态持久化。

3. **榜单生成与持久化**
   - 根据热度分值降序排序；相同热度时结合发布时间和标题稳定排序。
   - 通过 `HOT_NEWS_COUNT` 设置榜单数量，默认 10 条。
   - 热点记录按来源、URL 和日期组合唯一，支持每日归档，避免跨日覆盖。
   - 当日摘要保存在 `DailySummary`，热点保存在 `HotNews`。

4. **页面与管理后台**
   - 首页展示所选数据源的当日榜单和每日概览。
   - 历史页提供最近 30 天日期筛选，仅显示有数据的日期。
   - 调度后台支持数据源切换、任务新增、启停、删除和立即抓取。

5. **任务调度与数据维护**
   - 使用 `node-cron` 执行数据库中配置的抓取计划，并支持指定时区。
   - Seed 初始化默认调度任务；提供超过保留期限的热点与摘要清理逻辑。

## 可用于面试的技术要点

- **为什么按日建立复合唯一键？** 新闻 URL 可能多日持续出现在榜单中。如果只按来源和 URL 唯一，后续抓取会更新覆盖前一天记录。把日期加入唯一键后，幂等范围变为“来源 + URL + 当日”，既允许当天重复抓取更新，也保留跨日历史。
- **如何确保榜单排序可复现？** 主排序键为热度，次排序键为发布时间，仍相同时以标题作为确定性排序条件，最后按配置条数截取并重新编号。
- **为什么用工作流图？** 将抓取、去重、排序、摘要和保存拆为职责明确的节点，并用条件边处理空结果；后续可逐步扩展重试、审核或分析节点。
- **如何处理多源差异？** 各采集器统一输出 `RawHotItem`，下游节点只依赖统一结构；来源解析与榜单配置通过环境变量集中控制。

## 口径与边界

- 当前实现中的每日概览由榜单标题进行规则拼接；虽然依赖中包含 LangChain OpenAI 集成，但现行摘要节点并未调用 LLM API，简历不宜表述为“LLM 自动摘要”。
- 项目提供公开 RSS 数据抓取与页面归档能力；项目成果为工程功能，不包含未经测量的用户规模、采集准确率、性能提升比例或线上业务指标。
- 技术设计文档中的 Sina、东方财富、雪球等采集器属于代码中的探索性实现；当前运行时默认/允许配置的数据源以 CNBC、Yahoo Finance 和 all 聚合模式为准，不应将候选抓取器表述成稳定生产数据源。
